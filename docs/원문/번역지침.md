# 한의학 고전 원문 번역 지침

이 문서는 Codex를 포함한 어떤 LLM에도 공통으로 적용하는 한문 원서의 한국어·일본어·영어 번역 규약이다. 번역 대상은 `_가져오기/`가 아니라 교감과 검증을 마쳐 `docs/원문/<서명>(<문헌 ID>)/`에 정본으로 승격된 문헌이다.

## 번역 입력

각 문헌 폴더의 `translation-tasks.jsonl`을 입력으로 사용한다. JSONL 한 줄이 하나의 독립 작업이며 주요 필드는 다음과 같다.

- `source_id`: 원문과 번역을 연결하는 불변 식별자
- `parent_source_id`: 긴 조문을 나누기 전 상위 식별자
- `chunk_index`, `chunk_count`: 분할 조문의 순서와 전체 개수
- `book`: 서명
- `heading`: 권·편·절 또는 조문 제목
- `source_path`: 보존 원자료의 상대 경로
- `text`: 번역할 교감 원문
- `target_original`: 대응하는 정본 Markdown 파일

`text`가 번역의 기준 원문이다. 같은 폴더에 `표점본.md`가 있으면 문장 경계를 판단하는 보조 자료로 사용하되, 표점본을 근거로 글자를 추가·삭제·교체해서는 안 된다. `corrections-applied.json`과 `교감기록.md`는 이체자와 교정 사유를 확인할 때 참고한다.

## 절대 규칙

1. 입력의 `source_id`, 작업 순서, 작업 개수를 그대로 보존한다. 서로 다른 작업을 합치거나 하나를 누락하지 않는다.
2. 원문 파일, `translation-tasks.jsonl`, 표점본, 교감 기록을 번역 과정에서 수정하지 않는다.
3. 번역은 원문에 충실한 직역을 우선한다. 원문에 없는 병명, 병리 기전, 현대 의학적 설명, 치료 효과를 본문에 보태지 않는다.
4. 해석과 설명은 번역문에 섞지 않고 `translator_notes`에만 기록한다.
5. 판독 불가자, 의미가 확정되지 않은 이체자, 문법적으로 여러 해석이 가능한 구절을 문맥만으로 꾸며내지 않는다. 해당 부분은 대상 언어에 맞는 번역 유보 표시를 남기고 `unresolved`에 원문 구절과 사유를 기록한다.
6. 인명·서명·편명·처방명·본초명·경혈명은 대상 언어권의 한의학·동아시아 전통의학 표준 용어를 사용한다.
7. 처방 구성, 약물 용량, 숫자, 시간, 횟수, 경혈 위치와 금기 문구를 생략하거나 반올림하지 않는다. 전통 단위는 그대로 번역하고 현대 단위 환산은 번역문이 아닌 주석에서만, 근거가 있을 때 제시한다.
8. `不`, `勿`, `無`, `未`, `禁`, `忌`, `反`, `惡` 등 부정·금기 표현과 조건절을 반드시 보존한다. 주어와 목적어가 생략된 경우 확정할 수 없는 대상을 임의로 보충하지 않는다.
9. 운문, 가결, 맥결은 행 구분과 반복 구조를 보존한다. 산문으로 풀어 의미를 넓히지 않는다.
10. 번역문의 문장부호와 인용 부호는 대상 언어의 현대 출판 관행을 따른다. 원문의 고문 표점을 그대로 복사하지 않는다.

## 공통 용어 원칙

- 장부 개념은 처음 등장할 때 원문 한자를 병기하며, 현대 해부학의 장기와 함부로 동일시하지 않는다.
- 기(氣), 혈(血), 진액(津液), 영위(營衛), 삼초(三焦), 명문(命門)처럼 번역하면 뜻이 좁아지는 핵심 개념은 대상 언어의 통용 전문어를 사용하고 원문 한자를 병기한다.
- 증후와 병증은 가능한 한 표준 한의학 용어로 옮긴다. 현대 질환명과 일치한다고 확정할 수 없으면 현대 진단명으로 치환하지 않는다.
- 본초·처방·경혈은 표준명으로 옮기고 최초 등장 시 원문 한자를 병기한다. 서로 다른 약재를 비슷한 현대 생약명으로 통합하지 않는다.
- `曰`, `云`, `謂`가 인용이나 문답을 나타내면 화자를 보존한다. 주석, 본문, 후대 인용문이 섞인 경우 층위를 드러내 번역한다.
- 원문의 괄호 주석, 세주, 교감 삽입을 번역문에서도 괄호로 구분한다. `<ins>…</ins>`는 교감으로 보충된 원문임을 뜻하며 글자는 번역하되 필요하면 주석에 보충 사실을 밝힌다.

## 언어별 원칙

### 한국어 (`ko`)

- 인명·서명·편명·처방·본초·경혈은 표준 한국어 한자음으로 적고, 중국어 병음이나 일본식 독음을 한글로 음역하지 않는다.
- 핵심 전문어는 처음 등장할 때 `간(肝)`, `기(氣)`, `족삼리(足三里)`처럼 한자를 병기한다.
- 문장부호는 한국식 표점(`.`, `,`, `!`, `?`, `;`, `:`)을 사용하고 `。`와 `，`는 사용하지 않는다.
- 미확정 부분은 `[번역 유보: 원문 구절]`로 표시한다.

### 일본어 (`ja`)

- 현대 일본의 漢方·東洋医学 분야에서 통용되는 표준 용어와 자연스러운 일본어 문체를 사용한다. 한문을 일본 신자체로만 바꾼 결과를 번역으로 간주하지 않는다.
- 처方·生薬·経穴 명칭은 일본어권 표준 명칭을 우선하고, 혼동 가능성이 있으면 최초 등장 시 원문 한자를 병기한다.
- 고전의 臓腑 개념과 현대 해부학적 臓器를 구분하며, 미확정 부분은 `[訳保留：原文]`로 표시한다.

### 영어 (`en`)

- WHO 용어 및 영어권 Chinese medicine 학술 문헌에서 널리 쓰이는 표현을 우선하되, 의미가 좁아지는 핵심어는 번역어 뒤에 원문 한자와 필요 시 병음을 병기한다.
- 처방·본초·경혈은 일관된 영어 표준명을 사용한다. 병음만으로 대상을 식별하기 어려우면 원문 한자를 함께 둔다.
- 현대 생의학의 질병명·장기명으로 섣불리 등치하지 않으며, 미확정 부분은 `[translation withheld: source text]`로 표시한다.

## JSONL 출력 계약

대량 번역의 기본 산출물은 UTF-8 JSONL이다. 입력 한 줄마다 출력도 정확히 한 줄을 만들며 설명문이나 Markdown 코드 울타리를 덧붙이지 않는다.

```json
{"source_id":"N000:p003:s0001:t0001","parent_source_id":"N000:p003:s0001","target_language":"ko","translation":"옛날에 ….","translator_notes":[],"unresolved":[],"model":"사용한 모델명","status":"machine_translated"}
```

필드 규칙은 다음과 같다.

- `source_id`: 3문장 조각의 입력값을 한 글자도 바꾸지 않고 복사 (`<원래 source_id>:tNNNN`)
- `parent_source_id`: 조각을 만들기 전 `translation-tasks.jsonl`의 원래 `source_id`
- `target_language`: `ko`, `ja`, `en` 중 하나
- `translation`: 지정된 대상 언어의 직역문
- `translator_notes`: 번역 선택, 이체자, 다의적 구절에 관한 짧은 문자열 배열
- `unresolved`: 확정하지 못한 원문 구절과 사유를 담은 문자열 배열
- `model`: 실제 모델명과 가능하면 버전
- `status`: 최초 기계 번역은 항상 `machine_translated`; 사람 검수 전에는 `reviewed`나 `final`을 사용하지 않음

JSON 문자열 안의 실제 줄바꿈은 `\n`으로 이스케이프한다. 유효한 JSON 이외의 텍스트, 후행 쉼표, 주석, 동일 `source_id`의 중복 행을 만들지 않는다.

### 3문장 증분 규칙

번역 입력과 결과는 **원문 1–3문장마다 JSONL 파일 하나**로 저장한다. 파일명은 `part-NNNN.jsonl`이며 한 파일은 절대 3문장을 넘지 않는다. 파트가 번역되면 다음 파트를 기다리지 말고 즉시 저장·검증·Markdown 렌더링한다.

문장 경계는 검증된 `표점본.md`가 있으면 그 표점을 최우선으로 사용하고, 없을 때만 `translation-tasks.jsonl`의 `text`를 사용한다. 원래 한 `source_id`에 4문장 이상이 들어 있으면 반드시 나눈다. 조각 ID는 `<원래 source_id>:t0001`, `:t0002` 순으로 붙이고, 각 입력·출력 행에 원래 ID를 `parent_source_id`로 보존한다. 표점본과 원문을 안전하게 대응시킬 수 없거나 문장 경계가 불명확하면 임의로 잘라 번역하지 말고 오류로 보고한다.

번역은 문헌 전체가 완료될 때까지 메모리에 쌓아두지 않는다. 원문을 표점본의 문장 경계에 맞춰 먼저 조각으로 나눈 뒤, 연속된 **1–3문장만** 하나의 `part-NNNN.jsonl`에 넣는다. 한 입력 행에 4문장 이상이 들어 있으면 행 경계를 보존하려고 3문장 제한을 넘기지 말고, 반드시 `:tNNNN` 조각으로 나눈다. 각 파트는 번역이 끝나는 즉시 디스크에 저장하고 검증한 뒤 Markdown으로 렌더링한다. **3문장 초과를 허용하는 예외는 없다.**

모델별 원시 결과는 다음 위치에 둔다.

```text
docs/원문/_번역/<서명>(<문헌 ID>)/<언어 코드>/<모델명>/
├── parts/
│   ├── part-0001.jsonl
│   ├── part-0002.jsonl
│   └── ...
└── markdown-parts/
    ├── part-0001/
    ├── part-0002/
    └── ...
```

각 파트는 서로 겹치지 않는 연속 `source_id` 구간이어야 한다. 완료된 파트는 즉시 디스크에 기록하고 Markdown으로 렌더링한다. 실패한 파트만 다시 실행하며 이미 검증된 파트를 덮어쓰지 않는다. 같은 모델을 새로 실행할 때는 모델 버전이나 실행일을 구분한다.

## LLM에 전달할 기본 프롬프트

아래 프롬프트와 이 문서 전체를 함께 제공하고, 그 뒤에 `translation-tasks.jsonl`의 작업 묶음을 전달한다.

```text
당신은 한의학 고전 한문을 지정된 대상 언어로 옮기는 전문 번역자다.
대상 언어는 {target_language: ko|ja|en}이다.
제공된 번역 지침을 모두 준수하라. 각 입력 JSON 객체에 대해 source_id를 정확히
보존한 JSON 객체 한 줄만 출력하라. parent_source_id도 입력값을 그대로 복사하라. text만 번역 기준 원문으로 삼고 원문을 교정하거나
내용을 보충하지 마라. 직역과 역자 주를 분리하고, 확정할 수 없는 부분은 추측하지 말고
unresolved에 기록하라. 모든 행에 동일한 target_language를 기록하라. 출력 행의 수와
순서는 입력과 정확히 같아야 한다. 이 묶음이 끝나면 다음 묶음을 기다리지 말고 즉시 출력하라.
```

한 번에 너무 많은 작업을 주면 행이 누락될 수 있으므로 한 번의 호출에는 `part-NNNN.jsonl` 하나만 전달한다. 원래 `source_id`가 길면 `:tNNNN` 조각으로 먼저 나누고, 각 파트는 위 "JSONL 출력 계약"의 원문 1–3문장 기준을 엄격히 따른다.

## Markdown 결과 생성

JSONL 검증을 통과하면 다음 명령으로 사람이 읽을 Markdown을 생성한다.

```bash
python3 scripts/render_classic_translations.py \
  --book-dir 'docs/원문/海藥本草(C005)' \
  --results 'docs/원문/_번역/海藥本草(C005)/ko/모델명/parts/part-0001.jsonl' \
  --output 'docs/원문/_번역/海藥本草(C005)/ko/모델명/markdown-parts/part-0001' \
  --partial
```

렌더러는 `target_original`을 기준으로 원문 Markdown의 파일 구성을 그대로 재현한다. 예를 들어 `002-草部卷第二.md`의 번역은 임시 검수 단계에서 다음 위치에 생성된다.

```text
docs/원문/_번역/海藥本草(C005)/<언어 코드>/<모델명>/markdown-parts/part-0001/002-草部卷第二.md
```

각 `source_id`는 다음 구조로 출력된다.

```markdown
<!-- source-id: N000:p003:s0001 -->

## 원문

昔在黃帝……

## 직역

옛날 황제가…….

## 역자 해설

- 해석상 선택이나 미확정 사항을 기록한다.
```

원문은 `translation-tasks.jsonl`에서 기계적으로 복사하고 LLM이 재출력한 원문을 신뢰하지 않는다. 해설할 사항이 없으면 `### 역자 해설` 아래에 `- 없음.`이라고 쓴다.

모든 파트가 끝나면 파트 JSONL을 `source_id` 순서대로 결합해 렌더러를 `--partial` 없이 한 번 더 실행한다. 이 전체 실행은 누락·중복·순서 오류가 없는지를 검증하면서 최종 Markdown을 만든다. 사람의 대조 검수를 마친 파일만 해당 정본 폴더의 `번역/<언어 코드>/` 아래로 옮긴다.

```text
docs/원문/海藥本草(C005)/
├── 002-草部卷第二.md
└── 번역/
    ├── ko/002-草部卷第二.md
    ├── ja/002-草部卷第二.md
    └── en/002-草部卷第二.md
```

모델별 임시 Markdown을 정본의 `번역/`에 바로 덮어쓰지 않는다. 정본 번역에는 검수한 모델명·검수 상태를 문서 머리말에 기록하고, 여러 모델의 결과 중 채택하지 않은 파일은 `_번역/`에 남긴다.

## 검수 기준

번역 완료는 생성과 동일하지 않다. 최소한 다음 검수를 통과해야 한다.

1. 입력과 출력의 행 수, 순서, `source_id` 집합이 완전히 일치한다.
2. 빈 번역, 중복 ID, 잘린 JSON, 모델의 머리말·맺음말이 없다.
3. 숫자·용량·시간·횟수·부정어·금기·처방 구성의 누락 여부를 원문과 대조한다.
4. 인명·서명·처방·본초·경혈이 대상 언어권의 표준 용어로 일관되게 번역됐는지 확인한다.
5. `[번역 유보: …]`와 `unresolved`를 사람이 원문 및 판본 근거와 대조한다.
6. 기계 번역은 사람 검수 전까지 `machine_translated` 상태로 유지한다.

교감이 바뀌어 `translation-tasks.jsonl`의 `text`가 갱신되면 해당 `source_id`의 기존 번역도 재검수한다. 번역문이 이미 있다는 이유로 이전 원문에 대한 번역을 그대로 재사용해서는 안 된다.
